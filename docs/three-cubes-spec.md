# Three cubes: correctness contract

## 1. Equation and domain

The equation is x³ + y³ + z³ = k, where x, y, z, k ∈ ℤ. Negative integers and zero are allowed.

A search instance is (k, B), where B is an integer with B ≥ 0. Its domain is D(B) = {(x, y, z) : max(|x|, |y|, |z|) ≤ B}. The domain contains |D(B)| = (2B + 1)³ ordered triples and C(2B + 3, 3) canonical triples.

## 2. Solutions and symmetry

A valid solution has integer coordinates that are neither bool nor float and satisfies x³ + y³ + z³ == k exactly. Canonical form sorts the coordinates in ascending order: x ≤ y ≤ z. A permutation orbit has size 6 when all coordinates differ, 3 when exactly two agree, and 1 when all three agree.

Negation maps a canonical triple (x, y, z) to (-z, -y, -x). The first triple solves k if and only if its negation solves -k; the map preserves canonical order.

A trivial solution has some pair of coordinates that sums to zero. Its remaining coordinate is a cube root of k, so k is a perfect cube. Trivial solutions are included in results; triviality is a separate predicate.

## 3. Solver contract

`search(k, B)` returns exactly the set of canonical solutions in D(B), represented as a lexicographically sorted list. All future solvers must match the brute-force baseline exactly.

`triples_checked` counts candidate canonical triples evaluated; 0 ≤ triples_checked ≤ C(2B + 3, 3). `validate_result` checks soundness of any result without trusting the solver.

## 4. Mathematical facts and test oracles

For every integer n, n³ mod 9 ∈ {0, 1, 8}. If 3 divides n, then 27 divides n³. Otherwise n = 3m ± 1 and n³ ≡ ±1 (mod 9). A sum of three residues from {0, 1, -1} cannot equal 4 or 5 modulo 9, so k ≡ 4, 5 (mod 9) has no solutions. The modular solver (§8) uses this fact to return no solutions for such k without searching.

The solutions for k = 0 are exactly (-t, 0, t) for 0 ≤ t ≤ B (Euler's proof of Fermat's Last Theorem for exponent 3).

Two infinite families are:
- k = 1: (9t⁴, 3t − 9t⁴, 1 − 9t³).
- k = 2: (1 + 6t³, 1 − 6t³, −6t²).

Trivial-solution count. If k = n³ with |n| ≤ B, exactly B + 1 canonical solutions in D(B) are trivial; otherwise none are. Proof: a trivial solution contains a pair t, −t, so the third coordinate cubes to k and equals the unique integer cube root n. The solution is the multiset {−t, t, n} with 0 ≤ t ≤ B; distinct t give distinct multisets, and it lies in D(B) if and only if |n| ≤ B.

## 5. Arithmetic limits

Signed int64 brute force is safe only for B ≤ 1,454,083, the largest bound satisfying 3B³ ≤ 2⁶³ − 1. Known record solutions exceed 128-bit range when their coordinates are cubed. Use exact integer arithmetic throughout.

## 7. Conformance

Golden data is generated by independent ordered enumeration, not by the brute-force solver. It lists every k in each range, including entries with no solutions. Regenerate it with `python -m diophantine_search.testing.three_cubes_golden tests/data/three_cubes_golden.json`; never hand-edit it.

The `fast` set uses B = 30 and −100 ≤ k ≤ 100 on every run. The `wide` set uses B = 30 and −1000 ≤ k ≤ 1000 in the slow tier. The `slow` set uses B = 100 and −100 ≤ k ≤ 100 in the slow tier.

Add each new solver to `SOLVERS` in `tests/conftest.py`. It must pass every conformance check, including the slow tier, before acceptance.

## 8. Modular pruning

Lemma. For every m ≥ 1, if x³ + y³ + z³ = k, then z³ ≡ r (mod m), where r = (k − x³ − y³) mod m. Therefore z mod m lies in Z_m(r) = {c : c³ ≡ r (mod m)}. If Z_m(r) is empty, the (x, y) row has no solution; otherwise only z in those residue classes can be solutions. Completeness follows from the lemma, soundness follows from the exact check of every emitted triple, and order follows from visiting rows in (x, y) order and sorting z within each row.

A row can be skipped only when some residue is not a cube modulo m. Cubing modulo m is surjective if and only if m is squarefree and has no prime factor p ≡ 1 (mod 3). By the Chinese remainder theorem, it suffices to consider prime powers p^e. If e ≥ 2, the p^(e−1) multiples of p cube into the multiples of p³, a smaller set, so cubing is not injective and hence not surjective. If e = 1, zero maps to zero and the nonzero residues form a cyclic group of order p − 1. Cubing on that group is a bijection exactly when 3 does not divide p − 1, meaning p = 3 or p ≡ 2 (mod 3).

Moduli that skip rows include 4, with cubes {0, 1, 3}; 7, with {0, 1, 6}; 8; 9, with {0, 1, 8}; and 13, with {0, 1, 5, 8, 12}. Moduli 2, 3, 5, 6, 11, and 17 never skip rows, although z is still restricted to one class per row.

If m divides m′, `triples_checked` with m′ is at most `triples_checked` with m because classes modulo m′ refine classes modulo m. For the modular solver, `triples_checked` is zero for the modulo-9 exclusions. Otherwise it is the number of canonical triples in D(B) satisfying z³ ≡ k − x³ − y³ (mod m).

Over k ∈ [−100, 100] at B = 30, the exact reproducible totals are 6,234,627 checks (78.1% of brute-force work) for m = 1, 901,453 (11.3%) for m = 9, 131,307 (1.645%) for m = 63, and 11,043 (0.138%) for m = 819.

The default m = 819 = 7·9·13 is the product of 9 and the two smallest primes p ≡ 1 (mod 3), 7 and 13, giving three pairwise-coprime non-surjective cube-residue constraints. Larger moduli such as 819·19 check fewer triples but were slower in Python at feasible bounds because of per-class loop overhead. Powers of 2 such as 4 and 8 provide further non-surjective constraints. The default may be retuned after benchmarking.

Implementation note: in C and C++, the `%` operator can return negative values for negative operands; residues must be normalized into [0, m).

## 9. Cube-root row search

Uniqueness. The map n ↦ n³ is strictly increasing on ℤ, so each (x, y) has at most one integer z satisfying z³ = k − x³ − y³. The solver finds it with an exact integer cube root using integer Newton iteration and no floating point, valid for integers of any size.

Bounds lemma. For a canonical solution x ≤ y ≤ z ≤ B, 2y³ ≤ y³ + z³ = k − x³ and k − x³ − y³ = z³ ≤ B³. Also 3x³ ≤ k, which follows from the first inequality and x ≤ y. Hence

max(x, ⌈∛(k − x³ − B³)⌉) ≤ y ≤ min(B, ⌊∛⌊(k − x³)/2⌋⌋)

and x ≤ min(B, ⌊∛⌊k/3⌋⌋). Floor division is valid because y³ and x³ are integers. Conversely, if the exact root exists within these bounds, then y ≤ z ≤ B.

Modular row filter. By §8, a row (x, y) can contain a solution only if (k − x³ − y³) mod m is a cube residue. Equivalently, y mod m lies in Y_m(s) = {c : (s − c³) mod m is a cube residue}, where s = (k − x³) mod m. The solver iterates y only over these classes. The table has m·|cube residues| entries and is capped at 5,000,000.

Each surviving (x, y) row increments `triples_checked` once and performs one exact integer cube-root test, which decides whether the row's only possible z, the real cube root of k − x³ − y³, is an integer. For this solver, `triples_checked` counts candidate rows rather than explicit triples. It still satisfies the §3 bound because the number of canonical rows is at most C(2B + 2, 2) ≤ C(2B + 3, 3). If m divides m′, the count with m′ is at most the count with m.

Over k ∈ [−100, 100] at B = 30, the exact reproducible totals are 121,664 candidate rows (1.52% of brute-force triples) for m = 1, 52,796 (0.661%) for m = 9, 23,188 (0.291%) for m = 63, and 9,109 (0.114%) for m = 819. Counts measure candidates rather than cost: one cube-root test costs more than one triple check. Timing belongs to benchmarking.

The default is m = 819. In informal timing, m = 15561 was faster at B = 3000; the default may be retuned after benchmarking.

Implementation note: C and C++ integer division truncates toward zero. The bounds require floor division, so negative operands must be handled explicitly.
